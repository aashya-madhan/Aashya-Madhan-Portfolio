# Portfolio UI/UX refinement: Black and champagne gold theme

The implementation updates the portfolio with a premium black-and-champagne-gold theme, introduces a modal-based project details system, and refines layout consistency across all sections. The work follows a component-driven approach with TypeScript data structures for project content and maintains the existing Next.js 16/React 19/Tailwind CSS v4 stack.

**Watch for:** Modal accessibility implementation needs focus trap verification (likely), About section grid has 5 columns for 4 stat cards creating layout imbalance (confirmed), Hero name uses full gold gradient instead of flat champagne gold as briefed (confirmed), Contact card uses `break-words` but email may still break awkwardly on mobile (possible).

**Verdict**: NEEDS_CHANGES

## High-level view

The Projects section successfully implements the modal architecture with proper AnimatePresence, backdrop close, Escape-key handling, and body scroll lock, though focus trap implementation needs runtime verification. Project cards are compact and uniform with hover effects and a clear "View Details" cue. The data structure cleanly separates existing information from placeholder fields for future screenshots and additional content without inventing fake data.

Hero section applies a gold gradient to the name rather than flat champagne gold as specified, and all stat values correctly use #C5A568, though labels use #B8B5AE instead of the briefed #858585 muted color. The About section has a grid mismatch: `md:grid-cols-5` for only 4 stat cards, which will cause the last card to break to a new row on desktop.

Experience, Skills, Contact, and Resume sections implement the requested refinements with consistent styling, proper date alignment, uniform badge heights, equal contact card heights via flexbox, and a gold resume button with dark text. Global styling maintains the black-and-gold palette with no new colors introduced and no new npm dependencies.

## Project modal architecture and accessibility

ProjectModal.tsx implements AnimatePresence for enter/exit transitions, Escape-to-close, backdrop-click close, and body scroll lock via useEffect that sets `document.body.style.overflow = "hidden"` when open and cleans up on unmount or project change.

The focus trap queries focusable elements and cycles Tab/Shift+Tab within modal boundaries. This implementation looks correct but requires runtime verification across browsers and with dynamic content. Focus management targets the modal container (`tabIndex={-1}`) when opened rather than the first interactive element; this works for screen readers but keyboard-only users would benefit from close-button focus on open.

Modal sections render conditionally: introduction, problem statement, contribution, features, challenges, and results only appear if data exists and doesn't contain "coming soon". Screenshot placeholders show "Screenshot coming soon" in a bordered container when the `screenshots` array is populated. Modal has `role="dialog"`, `aria-modal="true"`, and `aria-labelledby`.

## Project card compactness and interaction

ProjectCard.tsx displays title, `line-clamp-3` description, first 3 tech badges, and a gold "View Details" CTA with ArrowRight icon. The card uses `flex-col h-full` with a spacer div (`flex-grow`) to push the CTA to the bottom, ensuring uniform height when descriptions vary in length. GitHub and Live Demo links are removed from the card; they appear only in the modal.

## Project data structure and placeholder discipline

projects.ts extends all three projects with `modalContent` and `screenshots`. Introduction and features derive from existing descriptions and highlights; contribution extracts known implementation details. Placeholder text marks challenges and results where no verified data exists. Screenshot paths follow `/projects/safepulse-1.jpg` pattern with TODO comments marking them for future replacement.

## Projects grid and section integration

Projects.tsx uses `grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6` for the responsive grid. Modal state is `useState<Project | null>` with onClick handlers on each card. The section includes `scroll-mt-20` to prevent navbar overlap when navigating via anchor links.

## Hero gold name and stat value styling

Hero.tsx applies a gold gradient to the name: `bg-gradient-to-r from-[#C5A568] to-[#DFC58F]`. The brief specified "champagne gold or a subtle champagne-gold gradient", but the example colors suggest flat gold was the primary intent. If flat gold is required, change to `text-[#C5A568]`.

Stat values (9.41, 3+, 2+, IEEE) correctly use `text-[#C5A568]`. Stat labels use `text-[#B8B5AE]` (body text color) instead of `text-[#858585]` (muted text color) specified in the brief. #B8B5AE is warmer and lighter than #858585; both are muted, but consistency with the brief means using #858585.

## About layout and stat card grid mismatch

About.tsx centers bio in `max-w-3xl mx-auto` with left-aligned text. The stat grid uses `grid-cols-2 md:grid-cols-5 gap-4` for 5 items: 4 stat cards (9.41 CGPA, 3+ Projects, 91% ML Accuracy) plus the "Building Tools" card. The code is internally consistent (5 columns for 5 items), but the brief described 4 stat cards. If only 4 were intended, the grid should be `md:grid-cols-4` and the "Building Tools" card removed or justified.

## Experience visual hierarchy and date alignment

Experience.tsx uses flexbox for date alignment: `flex flex-col sm:flex-row sm:items-start sm:justify-between gap-2`. On small screens, layout stacks; on larger screens, role aligns left and date aligns right with `sm:text-right`. Role uses `text-lg font-semibold text-[#F5F1E8]`, company links use `text-[#C5A568]`, dates use `text-sm text-[#858585] font-mono`.

## Skills badge uniformity and wrapping

SkillBadge.tsx uses `rounded-xl glass px-4 py-2.5` with 20x20px icons and `text-sm font-medium text-[#F5F1E8]`. Badges wrap via `flex-wrap gap-3`. Technology logos retain original colors; no CSS filters are applied.

## Contact equal card heights and consistent structure

Contact.tsx uses `grid md:grid-cols-3 gap-6` with each card having `h-full flex flex-col` for equal height. Icon containers are 56x56px with `bg-[#C5A568]/8` background and `border-[#403522]` border. Email card uses `break-words`, which avoids mid-word breaks but very long emails may still wrap awkwardly on narrow mobile screens (320px viewport needs testing).

## Resume button gold styling and contrast

ResumeCTA.tsx uses `bg-[#C5A568] hover:bg-[#DFC58F] text-[#080808]` for the primary button with dark text for contrast. Gold-tinted shadows (`shadow-[#C5A568]/25`) add depth.

## Global palette consistency and starfield opacity

globals.css defines champagne gold palette in CSS custom properties: `--color-accent: #C5A568`, `--color-accent-hover: #DFC58F`, background colors, and text colors. Starfield uses white stars with 0.25-0.4 opacity and the container has `opacity: 0.5`. No teal, cyan, green, bright yellow, or unrelated accent colors are present; palette is exclusively black, charcoal, and champagne gold.

## TypeScript type safety and data contracts

types/data.ts defines Project interface with optional `screenshots?: string[]` and `modalContent?: { introduction, problemStatement, contribution, features, challenges, results }`. All modalContent fields are optional. The interface is used consistently across projects.ts, ProjectCard.tsx, ProjectModal.tsx, and Projects.tsx. Optional chaining (`project.modalContent?.introduction`) prevents runtime errors when fields are absent.
